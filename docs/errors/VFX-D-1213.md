# VFX-D-1213

## Title
ReservedDependencyEnvironmentName

## Explanation
An entry in a managed dependency’s `env` map names a variable the engine sets for that dependency type. The engine refuses the override before container startup. Full and semantic validation report an `error` in `semanticDiagnostics`; schema-only validation does not perform this check.

Names and dependency types match exactly, including case. The rule checks the engine-owned names for `elasticsearch`, `minio`, `s3` (RustFS) and `azureservicebus`. It does not inspect values, resolve references, or discover variables reserved by Aspire or the container image. Custom service environments and external driver configuration are outside this check.

## Common causes
- Overriding `ES_JAVA_OPTS` on an `elasticsearch` dependency.
- Setting `MINIO_ROOT_USER` or `MINIO_ROOT_PASSWORD` on `minio`.
- Setting `RUSTFS_ACCESS_KEY` or `RUSTFS_SECRET_KEY` on `s3`.
- Setting `ACCEPT_EULA`, `MSSQL_SA_PASSWORD` or `SQL_SERVER` on `azureservicebus`.

## Fixes
- Remove the reserved entry and let the engine configure the managed dependency.
- For full control, declare the backend as a service with `image:` and point compatible steps at that service.
- Use the environment schema for name/value syntax. This diagnostic covers reserved names; it does not replace schema validation or engine validation of external configuration.
