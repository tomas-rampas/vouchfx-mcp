# VFX-D-1201

## Title
UnknownStepType

## Explanation
A step's `type` matches no step type the pinned engine bundles, which are the only types this server's
validator knows. Reported as validation data on a successful call — distinct from `VFX-E-1250`
(`StepTypeNotInCatalogue`), which fires when `describe_step_type` itself is asked about an unknown
type; this code instead describes a *suite* that references one.

From engine v1.2.0 the CLI can also load trusted external providers, so a type this code reports may
still be valid for the engine you run. `validate_suite` cannot check such a step, and `run_suite`
refuses the suite before starting the CLI.

## Common causes
- A typo in a step's `type` field (e.g. `http.rst` instead of `http.rest`).
- Referencing a step type from a different engine version than the one currently pinned (`ENGINE_PIN`).
- Copy-pasting a step from a different project whose engine defines additional step types this one does not.
- The type comes from a trusted external provider that the engine loads from `VOUCHFX_PROVIDERS` or `~/.vouchfx/providers` (engine v1.2.0 and later). `list_step_types` then lists it with `tier: "community"`, and `vouchfx validate` passes the suite.

## Fixes
- Call `list_step_types` to see every step type the installed engine loads, including any external provider's.
- Compare the type string carefully — dotted `<family>.<provider>` form, case-sensitive.
- Use `describe_step_type` on the corrected type to confirm its field contract before fixing the suite.
- If `list_step_types` lists the type with `tier: "community"`, do not rename it. Validate and run the suite with `vouchfx validate` and `vouchfx run` instead, because this server can neither validate nor run it.
